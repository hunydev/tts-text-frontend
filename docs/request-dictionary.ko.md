# 요청 사전 (2026-10-26)

엔진 사전(공통·시스템·도메인·고객·사용자 층)은 엔진을 만들 때 넣고 고정하면 바뀌지 않는다. 요청 사전은 고정된 엔진은 그대로 두고 **요청 하나(또는 스트림 하나)에만** 얹는 작은 사전이다. 대용량 사전은 엔진에 한 번 올리고, 고객사·통화·문서마다 다른 낱말은 요청 사전으로 준다.

## 항목

사전 파일은 탭으로 칸을 나눈 4칸 TSV다. 칸 안의 띄어쓰기는 키나 값의 일부다. `#`으로 시작하는 줄과 빈 줄은 건너뛴다.

```text
exact	ko-KR	2NE1	투에니원
exact	*	🍔👌	햄버거 좋아
exact	ko-KR	알콜 쓰레기	알쓰
exact	en-US	2NE1	two N E one
lexicon	ko-KR	en-US:Qorvex	코르벡스
lexicon	ko-KR	en-US:Qor Vex Labs	코르벡스 랩스
```

| 종류 | 2칸 | 3칸 | 4칸 | 뜻 |
|---|---|---|---|---|
| `exact` | 문장 언어 또는 `*`(모든 언어) | 입력, 적은 그대로 | 출력 | 그 언어로 정해진 문장에서 입력을 출력으로 바꾼다. 이모지, 줄임말, 여러 어절, 같은 언어의 영어 낱말 모두 된다. 출력은 다시 읽지 않는다. |
| `lexicon` | 읽을 언어 | `원어:낱말` | 읽기 | 다른 언어 낱말의 읽기(Apple 애플). 여러 낱말 이름도 된다. 같은 언어 낱말(영어 문장의 영어 낱말)에는 쓰이지 않으니 그때는 `exact`를 쓴다. |

엔진 사전의 같은 종류와 똑같이 맞춘다(소유자 결정 2026-10-26):

- **적은 그대로만.** 키 전체가 그대로 나와야 하고, 같은 문자가 이어지면 낱말이 계속된다고 본다. 알쓰는, 알쓰라서처럼 한글 뒤에 조사·어미가 붙으면 맞지 않는다. 바꾸고 싶은 형태는 따로 넣는다. 문자가 바뀌는 경계(2NE1의, 🍔👌 뒤)와 문장부호 앞은 맞는다.
- **문법 구간 안에서도.** 문법 규칙(제 N호, 수량 등)이 사전 항목을 덮을 만큼 길게 잡으면, 그 앞에서 분류를 끊고 사전 항목을 읽는다. 엔진의 도메인·고객·사용자 층 exact 항목도 같다.
- **대소문자 구분.** lol과 LOL은 다른 키다(`exact`). `lexicon` 낱말은 엔진처럼 ASCII 대소문자를 접는다.
- **띄어쓰기도 키의 일부.** 알콜 쓰레기와 알콜␣␣쓰레기는 다르다.
- **언어.** 같은 키라면 문장 언어로 적은 행이 `*` 행보다 먼저다. 엔진의 exact 규칙도 같은 층에서는 이렇게 정하도록 맞췄다(전에는 파일 순서).

## 우선순위

요청 사전 > 사용자 > 고객 > 도메인 > 시스템 > 공통. 요청 사전 행의 층은 `TTF_LAYER_REQUEST`(이름 `request`)이고, 스팬과 추적에 그대로 나온다. 리소스 적재(`ttf_resource_load`, `ttf_lexicon_add`)는 이 층을 받지 않는다.

## API

```c
ttf_dict_t *dict;
ttf_dict_create(&dict);
ttf_dict_add_exact(dict, "ko-KR", "2NE1", "투에니원");               /* 문자열은 복사 */
ttf_dict_add_lexicon(dict, "en-US", "ko-KR", "Qorvex", "코르벡스");
ttf_dict_load(dict, "tenant.tsv");                                  /* exact·lexicon 행만 */
ttf_dict_remove_exact(dict, "ko-KR", "2NE1");                       /* 엔진 사전의 읽기가 다시 보인다 */
ttf_dict_clear(dict);

ttf_normalize_with(engine, dict, text, length, &result);           /* dict가 NULL이면 ttf_normalize와 같다 */
ttf_stream_create(engine, callback, user, &stream);
ttf_stream_set_dict(stream, dict);                                 /* 첫 write 전에만, 뒤에는 TTF_ESTATE */
ttf_dict_destroy(dict);
```

- 같은 키를 다시 넣으면 바꾼다. 없는 키를 지워도 오류가 아니다.
- 잘못된 언어 태그, 빈 값, 탭·줄바꿈이 든 값, 잘못된 UTF-8은 `TTF_EINVAL`이다. 파일에 다른 종류의 행이나 칸 수가 틀린 행이 있으면 `TTF_ERESOURCE`이고, 파일이 없으면 `TTF_EIO`다.
- CLI: `ttf normalize|inspect|stream --request-dict FILE`. `--trace`와 함께 쓰면 추적에도 `request` 층이 나온다(`ttf_normalize_traced_with`).
- 웹 워크벤치: **발음사전 / 고객 리소스 실험**의 **요청 사전 TSV** 칸. 그 실행에만 적용되고, 정규화·상세 추적·스트리밍·청크 검증 모두에 쓰인다. 예제 선택의 **요청 사전 · 이모지·영문 이름**에 예가 있다.

## 스레드

- 엔진은 지금처럼 모든 스레드가 락 없이 함께 쓴다. 요청 사전은 그 요청의 것이다.
- **요청이 쓰는 동안 그 사전을 바꾸지 않는다.** 아무도 바꾸지 않는 사전은 여러 요청이 동시에 써도 된다(고객사별 사전을 미리 만들어 두고 요청마다 골라 붙이는 경우).
- 사전을 바꾸려면 그 사전을 쓰는 요청이 끝난 뒤 바꾸거나, 새 사전을 만들어 다음 요청부터 붙인다.

## 구현

- 요청마다 만들어지는 엔진 사본(스트림의 view)에 사전 포인터를 붙인다. 리소스 조회(`ttf_resource_entry`), exact 규칙 조회(`ttf_rule_match`), 키 길이 표, 여러 낱말 이름 색인이 사전을 먼저 본다. 팩 안에서 다시 부르는 정규화도 같은 사본을 받으므로 사전이 이어진다.
- 사전은 작은 해시 표(행이 늘면 커진다), 종류·언어별 키 길이, 63바이트 이상의 exact 키 목록, 여러 낱말 이름의 첫 낱말 색인을 갖는다. 항목을 지우면 색인을 다시 만든다.
- 사전을 붙이지 않으면 조회는 포인터 확인 하나만 늘어난다. 7개 언어 평가 세트 26,456문장의 출력과 스팬이 main과 바이트까지 같다.
- 테스트: `request_dictionary`(우선순위, 엔진 불변, 지우기, 긴 키, 여러 낱말 이름, 한 바이트씩 쓰는 스트림, 오류, 4스레드가 각자 다른 사전).

- 사전 없음과 main은 번갈아 12번씩 다시 재면 3,654 대 3,509문장/초로, 위 차이는 VM 흔들림이다.
- 1,000행까지는 사전이 없을 때와 거의 같다. 100,000행은 키 길이가 여러 가지라 문장 위치마다 조회가 늘어 20% 느리다. 큰 사전은 엔진 층에 두고 요청 사전은 작게 쓰는 것이 맞다.
- 사전 만들기: 1,000행 0.2ms, 100,000행 35ms.
