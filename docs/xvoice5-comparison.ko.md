# xvoice5 TN 비교 (2026-10-23, 최신 빌드로 다시 잼 2026-10-30, 정정 2026-11-02)

## 정정: cp949 밖 통화 기호 (2026-11-02)

10월 30일 재측정은 xvoice5를 패키지의 파이썬 래퍼(`xvoice5_tn/ko_tn.py`)로 돌렸다. 래퍼는 cp949에 없는 문자를 `_SUBST`의 대응 문자로 바꾸고, 대응이 없으면 지운다. `₩`(U+20A9), `¥`(U+00A5), `£`(U+00A3), `≈`(U+2248)는 cp949에 없고 대응도 없어서 지워진 채 엔진에 들어갔다. 그래서 `₩187,300`이 엔진에는 `187,300`으로 들어가 십팔만 칠천 삼백이 됐고, 이것을 xvoice5 TN이 원을 빠뜨리는 약점으로 잘못 적었다. 소유자가 `\187,300`(cp949 0x5C)을 넣으면 원으로 읽는다고 짚어 확인했다.

- 같은 문장을 `\187,300`(0x5C)이나 `￦187,300`(전각, cp949 A3DC)으로 넣으면 TN1.14.16은 십팔만 칠천 삼백원으로 읽는다. `₩`를 지우고 넣으면 십팔만 칠천 삼백이다.
- v3 한국어 2,000문장 중 이 네 문자가 든 문장은 23개(`₩` 12, `¥` 5, `£` 4, `⁰` 1, `≈` 1)다. 래퍼에 `₩→￦`, `¥→￥`, `£→￡`, `≈→≒`만 더해 다시 돌리니 TN1.14.16 출력이 22문장에서 바뀌었고, 아래 표와 항목의 TN1.14.16 값을 이 결과로 고쳤다(dev 통화 73/90 → 85/90).
- TN1.14.5는 같은 대응을 넣어도 `원십팔만 칠천 삼백`처럼 기호를 앞에 읽어 점수가 그대로다(새 빌드에서 고친 어순 문제).
- 남은 통화 오류는 소수 끝의 0이다(`€89.90` 팔십구점 구영유로, `$49.90` 사십구점 구영딸라).
- 비교 덱(TTF main 5e83a83 기준)도 같은 값으로 고쳤다: test 스팬 76.5% → 77.5%, 조정 83.4% → 84.4%, 오류 배수 4.8 → 4.6배, TTF만/xvoice5만 329/21 → 309/22, 통화 형태 20 → 6곳.
- 실제 서비스가 같은 래퍼를 쓴다면 사용자가 쓴 `₩` `¥` `£`도 지워진다. 래퍼의 `_SUBST`에 위 네 대응을 더하면 된다.

- **입력:** 시험 문장은 사용자 단어와 시스템 사전 숫자가 하나씩 든 짧은 문장 1,000개(평균 29자, 신제품 QX0028 모델과 회원 1524798님 확인)다. v3는 소유자 평가셋 v3 한국어 중 cp949로 그대로 옮겨지는 997문장(평균 58자)이다. 날짜·단위·통화 같은 형태가 여러 개라 시험 문장보다 느리다.
- **적용:** 두 엔진 모두 두 사전을 함께 적용한다(신제품 큐엑스영영이팔 모델과 회원 일오이사칠구팔님 확인). xvoice5는 사용자 사전 단어 뒤 띄어쓰기를 지운다(큐엑스영영이팔모델과).
- **TTF:** 사용자 사전 크기와 거의 상관없다. v3 열의 0.33–0.48ms 차이는 사전 크기 순서와 맞지 않는 측정 흔들림이다. 준비 1.1–1.3초, 약 220MB.
- **xvoice5:** 준비 0.38–0.40초, 79MB(최고 109MB). 사용자 사전이 없으면 오히려 느리다. CPU 샘플로 보면 사용자 사전이 없을 때 `IsReplacedText`가 시간의 약 30%를 쓰고, 사용자 사전을 주면 이 함수가 불리지 않는다. 두 경우 모두 `ApplyUSRDict`와 libc 문자열 함수 시간이 남아, 요청마다 시스템 사전을 훑는 것으로 보인다(함수 이름과 측정에서 본 추정).

### 실제 문장에 사전 낱말을 섞은 시험 (2026-10-26)

v3 한국어 997문장(평균 81자가 됨)마다 사용자 사전 낱말(QX0000–QX0099) 하나와 시스템 사전 숫자(7자리) 하나를 넣었다. 사용자 낱말은 405문장에서 실제 주어 자리를 바꾸고(국회 기획재정위원회는 → 국회 QX0099는) 나머지는 앞에 `QX0075 측은`을 붙였다. 숫자는 74문장에서 개수·번호 자리를 바꾸고(사업장 48곳 → 1842950곳) 나머지는 끝에 `(접수 번호 1488269번)`을 붙였다. C 직접 호출, 한 스레드, 3회 중앙값, 문장당 ms.

| 사전 | TTF | xvoice5 | 배 |
|---|---|---|---|
| 없음 | 0.42 | 1.28 | 3.0 |
| 사용자 사전 100행만 | 0.43 | 1.37 | 3.2 |

- **적용률:** 사용자 낱말은 두 엔진 997/997. 시스템 숫자는 xvoice5 997/997, TTF는 처음 995/997이었다. `제 1231987호`처럼 제와 숫자 사이가 띄어진 2문장에서 서수 문법(제 N호)이 숫자를 먼저 가져가 `제백이십삼만 천구백팔십칠 호`로 읽었다. 사전 항목이 문법 구간 안에 있으면 그 앞에서 분류를 끊도록 고친 뒤 997/997이고 속도는 같다(0.42–0.47ms).
- 두 문장 세트는 길이와 내용이 달라서 짧은 시험 문장(0.07ms)보다 수치가 크다. 엔진끼리는 같은 세트 안에서 비교한다.

## 소유자 결정 (2026-10-23)

- 범위 줄임(사오십 분)은 유지. 고유어 단위 범위는 앞 수에도 단위(두 시간에서 네 시간), 한자어 단위는 앞 수만(이에서 사 층).
- 섭씨·시속처럼 앞에 붙는 말은 양쪽에, 단위는 한 번: 섭씨 육십에서 섭씨 칠십 도.

- 소수+억·조는 쓴 대로(삼 점 오억 원), 만은 셈(1.25만 일 점 이오만)만; 3.5만 원은 삼만 오천 원.
