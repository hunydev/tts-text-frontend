# TN 개선 회차 기록

회차마다 약점 영역 2–3개를 고르고, 하위 에이전트가 쓴 150줄 이상의 `{표기|읽기/대안}` 평가셋으로 잰다.
처음 측정은 코드를 커밋으로 고정한 뒤에 하고, 수정은 일반 규칙과 어휘집으로만 한다.
점수는 문장 정확도이며 세 가지 설정으로 잰다: 기본, CMU(영어 발음 사전), localize+CMU.
2회차부터는 같은 셋을 main 빌드로도 재서 브랜치와 비교한다.

회차를 닫는 조건: 한국어 릴리스 벤치마크(`korean_quick.py`) 순손실 0, 소유자 평가셋 출력 변화 0, quick CI_EXIT=0.

## 1회차

- 셋: `~/arw/rounds/r1.jsonl`. 기준 코드는 main 2261851.
- 처음 측정 92.5%는 넓히기 전 셋 기준이다. 검토에서 둘 다 맞는 읽기(조사 대안, PC 피씨가, Top 10 탑 텐, v2.1.3 브이/버전 등)를 넓힌 뒤 같은 코드는 93.8 / – / 94.4였다.

수정:

- 라벨 번호: 영어 단어 뒤 숫자가 마침표나 쉼표로 끝나는 곡명(`Part 2.`)도 번호로 읽는다.
- `EP.1`, `Ep. 3`: `abbreviation_number_case`로 대소문자 혼합 키만 에피소드로 읽는다. 모두 대문자인 `NO.1` 넘버원은 그대로.
- 어휘집: dune 듄, episode 에피소드.

해 보고 되돌린 것:

- 버전 접두 `v2.1.3` → 버전: 소유자 ko 참조 6문장이 브이로 읽어서 되돌렸다. 셋은 둘 다 허용으로 넓혔다.
- `(주)` 주식회사, `(유)`, `(사)`, `(재)`: 벤치마크 참조가 갈린다(3건 중 확장 1, 표기 유지 2). 손익 +1/−2라서 뺐다. ㈜는 이미 주식회사로 읽으므로 소유자 결정이 필요하다.

남은 과제: `3%→5%` 화살표(…에서 …로), `≥ 60점` 어순(육십 점 이상), `①` 첫째, `1+1` 행사(원 플러스 원), `(주)` 정책.
