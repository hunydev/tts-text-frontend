# 실제 한국어 입력에서 고른 발음 사전 보강

2026-09-28. 사용자 요청에 따라 공통 누락 발음은 기본 사전에, 읽기 선택은
명시적으로 적용하는 사용자/고객 사전에 둔다. **기본23항목(별칭 포함24키), 선택형9키**.
원본 관리 파일은 `lexicons/ko-KR/usage-additions-v22.jsonl`, 출처는
`lexicons/sources/usage-v22.json`이다. Core·언어 판별·숫자 규칙·ABI 변경은 없다.

## 수집과 선택 기준

`benchmark/evaluators/lexicon_candidates.py`가 완료된 한국어 보고서의 원본 구간과
실제 출력을 모은다. 대소문자와 key 공백을 기존 사전 compiler와 같은 방식으로 묶고,
참조 읽기별 빈도·현재 출력·미일치·정렬 실패·구조 경고·엔진 의미 분류를 보존한다.
숫자만 있는 키, 지원하지 않는 복합 key는 사전 후보에서 구분한다. 후보 순위는
**구간 빈도**이지 개선될 문장 수가 아니다. 사전이나 정답을 자동 생성하지 않는다.

횟수 개선 후 보고서에서 지원하는 lexical shape 후보4,290키/13,869구간을 모았다.
미일치5,434구간에는 정렬 문제·단위 해석·참조의 읽기 차이도 포함되어 있다.
지원하지 않는 형태5,705구간은 별도 집계했다. 외부 후보·빈도·문장 ID는 ignored
`artifacts/tn/ko-lexicon/candidates-v1.json`에 있고 제품 사전으로 bulk import하지 않는다.

| 대표 후보 | 관찰 | 처리 |
|---|---|---|
| PIN | 141구간의 참조는 핀; 엔진은 주로 철자 읽기 | 기본 핀, 철자 읽기는 사용자 override 가능 |
| GS25 | 43구간에서 기존 숫자 코드 읽기와 브랜드 읽기가 다름 | 브랜드 전체 키를 지에스이십오로 선언 |

| XL / L / KF94 | 사이즈·단위·식별 코드에 따라 읽기가 다름 | 단일 기본 발음으로 강제하지 않음 |

문장 전체가 계속 불일치여도 변경된 구간을 함께 점검한다. 개선된 문장 수만 보면
이미 오답인 문장 안의 추가 오독이 숨는다. 허용형 차이를 참조 오류로 단정하지 않는다.

## 사용자 선택형 적용

파일: `resources/customers/reading-preferences/ko-KR/lexicon.tsv`.
이 파일은 **system manifest에 없고**, 명시적으로 로드할 때만 적용된다.
기존 User > Customer > Domain > System 우선순위를 그대로 사용한다.

| 키 | 선택형 |
|---|---|
| TV / CCTV | 티비 / 씨씨티비 |
| OLED | 올레드 |
| K3 / SM3 / XM3 / QM3 | 케이쓰리 / 에스엠쓰리 / 엑스엠쓰리 / 큐엠쓰리 |
| S-OIL | 에스오일 |
| MY | 마이 |

모든 항목을 사용할 필요는 없다. 업무에 맞는 행만 새 고객 파일로 복사·편집한다.
이 프로필은 이메일의 `my` 등 동일 key가 발음 조회에 쓰이는 곳에도 적용된다.
문장별 다른 읽기가 필요하면 User lexicon/명시 제어를 요청 단위로 사용한다.

```sh
build/ttf normalize --output-mode speech 'TV를 시청합니다.'
# 티브이를 시청합니다.
build/ttf normalize --output-mode speech \
  --customer resources/customers/reading-preferences/ko-KR/lexicon.tsv 'TV를 시청합니다.'
# 티비를 시청합니다.
```

웹 첫 화면의 **사용자 사전 · 티비/올레드/차종 읽기** 예제를 선택하면 고객 TSV
입력란에 이 파일의 내용이 채워진다. 행을 편집한 뒤 해당 요청에 적용할 수 있다.
공통23항목은 `/lexicon`에서 검색·근거 확인·사용자 발음 시험·TSV 내려받기가 가능하다.
`lexical-coverage-v22` corpus에는 기본/선택형 기대값을 구분해 등록했다.

## 반복 가능한 검증

```sh
python3 benchmark/evaluators/lexicon_candidates.py \
  --report benchmark/generated/ko-release/reports/20260928-frequency-v3 \
  --out artifacts/tn/NEXT/candidates.json
python3 tools/lexicon/manage.py validate
python3 tools/lexicon/manage.py build --check
ctest --test-dir build --output-on-failure -R 'lexical_|lexicon_'
```

수집기는 완료 상태와 SQLite checksum을 확인하고 입력 변경·기존 output 덮어쓰기를
거부한다. 원본 사전 JSONL을 수정한 후 `manage.py build`로 TSV를 생성한다.
생성 TSV는 직접 편집하지 않는다. 선택형 customer 예제는 사람이 편집하는 파일이다.

자체36계약은 후보 실행 전에 작성했다. 초기 English 원문 보존 검사1건은 기존
speech의 약어 철자 읽기와 혼동해 `speech`로 작성했으므로 `text`로 모드만 정정했다.
기대 문자열은 바꾸지 않았고 원본/사유는 `reference-mode-correction.json`에 보존했다.
`Please use PIN and PASS.`의 speech 출력은 변경 전후 동일하며 한국어로 변환하지 않는다.
MY는 전역 읽기가 이메일 회귀를 일으켜 사용자 scope로 옮겼고 기대 읽기는 유지했다.
기존 회귀 corpus의 기대값은 수정하지 않았다.

기존 ALNUM_TERM은 사전에 있는 단어+숫자에 원어 수사 정책을 적용한다. 따라서
`PRO` 등록은 `PRO360` 두 사례와 `pro5549` 식별번호 한 사례의 숫자 읽기에도
영향을 준다. 변경 전후 모두 제공 참조와 불일치하며, 이를 개선 건수로 세지 않았다.
값 손실은 없지만 식별번호의 원하는 자리별 읽기는 별도 제어/전체 키 사전이 필요하다.
단어 사전 등록이 붙은 숫자의 읽기 선택에도 영향을 줄 수 있다는 후속 검토 사례다.

기본 분절에서36건의 기대 text/metadata를 확인하고, 기본/매우 짧은 분절 각각에서
2,110개 byte 분할의 batch/stream text·span·trace 동일성을 확인한다. 작은 분절 목표는
기존 문맥 창 자체를 바꾸므로 **서로 다른 분절 설정 간 출력까지 같다는 보장은 아니다**.
예를 들어 1자 목표에서는 PIN이 뒤 한국어 문맥과 나뉠 수 있다. 이는 사전 추가 전부터
있는 제한이며 이번에 문맥 router를 변경하지 않았다.

전체 제공 Training 자료 재측정 결과는 HANDOFF와 `/ko-quality`에 기록한다.
기본 보고서에는 위 사용자 프로필을 적용하지 않는다. 선택형의 효과를 기본 정확도에
합산하지 않으며, 원본 참조·미채점·정렬 실패 분모도 유지한다.
