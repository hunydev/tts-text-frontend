# 일본어 팩 (ja-JP) 1단계

2026-10-08, 프로젝트 오너 요청. 대상 TTS 모델(VoxCPM2)은 토크나이저 없이 한자와 가나를
그대로 받아 읽으므로(일본어 CER 2.40%), 이 팩은 **모델이 틀리기 쉬운 부분만** 바꿉니다.

## 원칙

- 숫자, 조수사, 날짜, 시간, 통화, 단위는 **히라가나**로 씁니다: `3本` → `さんぼん`.
- 단위 이름과 로마자 글자 이름은 **가타카나**로 씁니다: `5kg` → `ごキログラム`, `USB` → `ユーエスビー`.
- 한자와 가나는 그대로 둡니다. 한자 읽기(KanjiNormalizer)는 하지 않습니다. 한자 숫자(`三人`)도
  1단계에서는 그대로 둡니다.
- 로마자 단어(`iPhone`, `I love you`)는 그대로 둡니다. 2~4자 대문자 약어는 글자 이름으로 읽습니다.
  일본어 옆에 붙은 로마자 한 글자도 글자 이름으로 읽습니다(`Aランチ` エーランチ, `ビタミンC`, `x軸`). 단, 앞뒤 한 칸 안에 영어 단어가 있으면 영어로 둡니다(`a pen`).
  단어처럼 읽는 대문자 약어는 `latin_word`(`NATO` ナトー, `LINE` ライン, `JPEG` ジェイペグ)를 따릅니다.
  `No.` ナンバー(`No.1` ナンバーワン), `etc.` エトセトラ, `vs.` バーサス, `Mr.` ミスター는 `latin_abbreviation`, `1st` ファースト부터 `20th`까지는 `latin_ordinal`을 따릅니다
  (`resources/languages/ja-JP/rules/latin.tsv`, 2026-10-08).
- `第`, `目`, `午後`처럼 숫자 옆 한자는 그대로 둡니다(`第1回` → `第いっかい`).

## 언어 선택

- 요청 언어가 `ja-JP`로 **선언된 경우에만** 동작합니다(`context ja-JP declared_only 1`).
- 한국어, 영어 요청에서는 점수도 분류도 내지 않습니다. 점수 0인 선언 전용 팩은 문맥 점수
  추적에서도 빠지므로 기존 추적(v0.18 기준)은 그대로입니다.
- 가나와 한자 문자 체계(script_score 100), 로마자(1, 영어 팩보다 낮음)를 주장하지만 core는
  선언 전용 팩의 문자 체계 점수를 다른 언어 요청에서 무시합니다. 그래서 한국어 문장 속 가나는
  여전히 문장 언어 투표에 끼지 않습니다. ja-JP 요청에서는 이 점수 덕분에 최종 음성 출력 단계가
  가나, 한자, 로마자를 그대로 둡니다(`iPhone`).
- 한국어 요청 안의 가나 읽기(`--kana korean`)는 기존 한국어 기능 그대로입니다.

## 조수사와 음 변화

`counter ja-JP <조수사> <읽기>:<부류>[:<기준 조수사>]` 행이 데이터입니다.
부류는 숫자 끝(1~9, 10, 100, 1000, 10000)에 따라 음 변화를 정합니다.

| 부류 | 예 | 변화 |
|---|---|---|
| h | 本 匹 杯 | 1·6·8·10·100 촉음+반탁음(いっぽん), 3·1000·10000 탁음(さんぼん) |
| f | 分 | 1·6·8·10·100 촉음+반탁음(いっぷん), 3·4 반탁음(さんぷん) |
| k / k3 | 個 回 / 階 軒 | 1·6·8·10·100 촉음(いっこ); k3은 3에서 탁음(さんがい) |
| s / s3 | 歳 冊 週間 / 足 | 1·8·10 촉음(はっさい); s3은 3에서 탁음(さんぞく) |
| t | 点 頭 | 1·8·10 촉음(いってん) |
| p10 | % ページ | 10만 촉음(じゅっパーセント) |
| w | 羽 | 3 탁음(さんば), 6·8·10·100 촉음+반탁음(ろっぱ) |

특수 읽기는 `counter_reading`입니다. `人:1 ひとり`처럼 값 전체, `時:*4 よじ`처럼 끝자리
(14時 じゅうよじ)를 키로 씁니다. 날짜의 1일은 `date_day:1 ついたち`이며 `月` 바로 뒤의 `日`에만
씁니다. 앞에 월이 없는 `1日`은 기간(いちにち)으로 읽습니다.
`日間`, `時間`, `年間`, `分間`은 기준 조수사의 읽기에 `かん`을 붙입니다(3日間 みっかかん).

## 숫자

- 만 단위로 읽습니다: `12,345,678` → `せんにひゃくさんじゅうよんまんごせんろっぴゃくななじゅうはち`.
- 숫자 뒤에 쓴 `千 万 億 兆`은 숫자에 합칩니다: `1万円` → `いちまんえん`, `1億2000万`.
- 소수: `3.14` → `さんてんいちよん`, `1.5` → `いってんご`, `0.5` → `れいてんご`.
- 범위 `3〜5個` → `さんからごこ`, 분수 `1/2` → `にぶんのいち`, `3分の1` → `さんぶんのいち`.
- 범위 표시 `〜`/`～`/`~`: 한자·숫자 뒤에서는 から (`午前10時〜午後3時` → `午前じゅうじから午後さんじ`, `月曜〜金曜` → `月曜から金曜`).
  히라가나 뒤, 또는 가타카나 뒤에서 가나·문장 끝 앞이면 장음 ー (`すご〜い` → `すごーい`, `ス〜パ〜` → `スーパー`), ん/っ/ー 뒤에서는 생략 (`speech_kana_lengthening`).
- 조수사 추가(2026-10-09): 箱(ひとはこ) 食 世帯 級 次 世 世代 週 畳(4畳半 よじょうはん) 坪(ひとつぼ) カ所 光年 丁目 番町 番地 強 弱 均 対 通り(とおり)
  児 貫 票 棟 隻 艘 基 両 膳 錠 区 球 周 種類 車線 語 切れ 袋 口 株 缶 次元. 画는 画素·画面과 겹쳐 넣지 않았습니다.
- `何`+조수사는 なん에 3과 같은 음 변화를 붙이고, 3의 특수 읽기(みっか, みっつ)는 쓰지 않습니다(`何本` なんぼん, `何階` なんがい, `何日` なんにち). `何か`, `何でも`는 그대로 둡니다.
- 비율·점수(2026-10-09): `N:M`, `N-M` 근처에 단서 말(score_cue 勝 負 引き分け 試合 …, ratio_cue 比 割合 縮尺)이 있으면 たい로 읽습니다(`3-2で勝利` さんたいに, `1:20の縮尺` いちたいにじゅう).
  콜론 뒤가 한 자리 숫자이면 시각이 아니라 비율로 봅니다(`16:9` じゅうろくたいきゅう). `@score` 제어도 たい로 읽습니다. 단서가 없는 `10:30`은 시각입니다.
- `10²` じゅうのにじょう, `2の3乗` にのさんじょう, 하이픈 범위 뒤 조수사 `3-5人` さんからごにん.
- 전화번호는 숫자를 하나씩 읽고 묶음 사이에 `の`를 넣습니다.
- 버전 `v1.2.3`/`Ver.2.0` → `バージョンいってんにてんさん`(1과 10은 てん 앞에서 촉음), IP `192.168.0.1` → 마디마다 숫자를 하나씩 읽습니다.
  `PM2.5`, `F2.8`처럼 글자 뒤 소수는 소수로 읽고, `F-15`는 하이픈 없이 `エフじゅうご`로 읽습니다.
- 수식 `x=3` → `エックスイコールさん`. 연산자는 `math_operator`(たす ひく かける わる イコール)를 따릅니다.
- 기호는 가나 읽기 `speech_symbol`(`−` マイナス, `★` ほし, `→` みぎやじるし, `©` コピーライト, `〒` ゆうびん)을 먼저 씁니다.
  표에 없는 기호는 CLDR 일본어 이름(`resources/unicode-fallback/ja.*`)으로 읽고, 영어 이름은 쓰지 않습니다.
- 전각 숫자는 기존 폭 정규화로 반각과 같이 읽습니다.

## 문장 분할

일본어는 문장 끝 `。！？` 뒤에 공백을 쓰지 않습니다. 이제 이 문장 부호 뒤에 공백이 아닌 글자가
오면 문장이 끝납니다(닫는 괄호와 따옴표, 이어지는 문장 부호는 제외). 긴 구절은 `、`에서 나누고,
공백도 쉼표도 없는 글은 최대 길이에서 가나/한자 사이를 자릅니다. 이 규칙은 언어와 무관하지만
한국어, 영어 글에서는 이런 부호가 거의 나오지 않아 벤치마크가 바뀌지 않습니다.

## 2단계 (2026-10-08)

- **가나 문장 자동 판별.** 한국어·영어 요청에서도 아래 조건의 문장은 일본어 문장으로 보고, 문장 전체를
  일본어 팩이 읽습니다(한국어 분기를 타지 않음). 리소스 `context ja-JP kana_sentence 1`.
  - 한글이 하나도 없을 것. 한글이 있으면 한국어 문장입니다(`「ありがとう」라고 쓴 카드를 3장` → 세 장).
  - 히라가나가 한자·가타카나와 한 단어에 있거나(`明日は`), 숫자·단어에 공백 없이 붙어 있거나(`3時に`,
    `iPhoneを`), 가나만 있고 로마자 단어가 없을 것.
  - 영어 문장 속 홀로 선 가나 단어는 근거가 아닙니다(`I read ありがとう 5 times.` → five).
  - 가타카나만 있는 것은 근거가 아닙니다(`오늘 サッポロ 3개` → 세 개).
  - 한자만 있는 문장은 요청 언어를 따릅니다(중국어 팩이 생기면 중국어 우선).
  - `--kana korean`, `--hanja korean`, `matrix=declared`에서는 적용하지 않습니다.
- core: 선언 전용 팩의 분류기는 그 팩이 문맥 언어인 토큰에서만 호출합니다.
- 이메일·URL: 기호 이름(アット, ドット, コロン, スラッシュ)과 도메인 단어(コム, イグザンプル)로 읽습니다.
  1단계에서는 ja-JP 요청에 주소가 있으면 요청이 실패했습니다.
- 기호: ① まるいち, ⑴ かっこいち, Ⓐ エー, ASCII 기호와 그리스 문자 이름, `R&D` アールアンドディー.
- 요일: `12月25日（水）` → `…すいようび`.
- 제어: `@year`(ねん), `@version`(ブイにてんいち…), `@ordinal`(だいさん), 숫자가 섞인 `@alphabet`.
- 계약 `ja_phase2_v37` (21).

## 한자 숫자 (2026-10-08, 프로젝트 오너 결정)

VoxCPM2가 한자 숫자를 중국어로 읽거나 음 변화(三本 さんぼん)를 틀릴 수 있어, **일본어 문장 안에서만**
한자 숫자를 아라비아 숫자와 같이 읽는다. 나머지 한자는 그대로 둔다.

- 바꾸는 경우: 조수사가 붙음(`三本` さんぼん, `一人` ひとり, `十月八日` じゅうがつようか), 자릿수 구조
  (`二千二十四`, `三十五歳`), 자리 숫자 표기(`二〇二四年`, `一九八四年`; 〇이 있거나 세 자리 이상).
  `三分の一` さんぶんのいち, `一日中` いちにちじゅう.
- 그대로 두는 경우: 혼자 있는 `一`·`二`(`第一に`, `一緒`), 혼자 있는 `十`·`百`·`千`(`千葉`), `時` 뒤가 아닌
  `十分`(じゅうぶん일 수 있음), 한자 앞의 `Nつ`(`四つ葉` よつば, `三つ子`), 숫자처럼 보이는 단어
  (`resources/languages/ja-JP/rules/kanji.tsv`의 `kanji_word`: 八百屋, 三日月, 五月雨, 十人十色, 一行 …).
- 한국어 문장과 한자만 있는 문장은 손대지 않는다.
- SudachiDict pip 패키지에는 이진 사전만 있어 어휘 목록을 바로 뽑을 수 없었다. 예외 사전은 우리
  규칙이 실제로 바꾸는 단어만 손으로 정리하고 JSUT 한자 숫자 문장 503개로 검사했다.
- JSUT 한자 숫자 문장은 읽기기(pyopenjtalk)가 한자 숫자를 이미 잘 읽어 이 작업의 효과가 드러나지
  않는다(회귀 방지용). 처음 13문장 손실 중 실제 오류(三分の一, 四つ葉, 一日中, 一晩, 第一人者 …)는
  고쳤고, 남은 손실은 읽기기 효과(は를 조사로 읽음)와 읽기 변형(七人 しちにん/ななにん)이다.
  효과는 VoxCPM2 청취 비교로 확인해야 한다.
- 계약 `ja_kanji_numerals_v39`. 1단계의 "한자 숫자는 그대로" 계약 행은 Was 기록과 함께 바꿨다.

## 측정 (2026-10-08)

JSUT BASIC5000 읽기와 비교한다(`docs/japanese-benchmark.ko.md`, 워크벤치 `/ja-quality`). 숫자 문장
253개에서 우리 203, pyopenjtalk 단독 199, wetext 196, NeMo 196 문장 일치. 숫자 구간 정확도 96.6%
(조정 100%). 측정에서 찾은 빈틈은 계약 `ja_bench_fixes_v38`로 고쳤다.
