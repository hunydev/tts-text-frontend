# 중국어(간체) 팩 zh-CN (1단계, 2026-10-11)

프로젝트 소유자 요청: 간체부터 하고, 원어민 검수는 Claude가 맡는다. 0단계 측정은 [chinese-phase0.ko.md](chinese-phase0.ko.md)에 있다.

## 언제 동작하나

- **요청 언어가 zh-CN일 때:** 한글·가나를 뺀 모든 토큰을 이 팩이 읽는다.
- **다른 요청 속 한자 문장일 때 (`han_sentence`):** 다음 조건을 모두 만족하면 문장 전체를 중국어 팩이 읽는다.
  - 한글과 가나가 없다.
  - 한자가 2자 이상이고, 로마자 단어 수의 두 배 이상이다. 숫자에 붙은 단위 글자(60km/h)는 단어로 세지 않는다.
  - 간체가 아닌 글자(`han_foreign`)가 없다. 일본식 신자체(駅 円 図 発)와 번체(國 時 這 們)를 합해 249자다.
- **라우팅하지 않는 경우:** 요청 언어가 가나 문장을 받는 팩(ja-JP)일 때, 한국어 `--hanja/--kana korean` 옵션일 때, `matrix=declared`일 때.
  - 그래서 일본어 요청 속 한자 문장, 한국어 한자 문장(大韓民國), 일본어 한자 문장(東京駅, 午前9時)은 이전과 같다.
- **분류 독점:** 중국어 문맥에서는 중국어 팩만 분류한다. 한국어·영어 팩이 수식이나 범위를 자기 말로 읽던 문제(1+1=2가 일 더하기 일)를 막는다.
- **기존 계약의 정책 변경:** `unicode_fallback_v24`의 한국어 요청 `北京 🍔`는 한자 문장이 되어 `北京 汉堡`가 됐다 (Was: `北京 햄버거`).
- **이전 동작:** 한국어 요청의 `我买了2个苹果。`는 `我买了이个苹果。`, 영어 요청의 `他得了第2名。`는 `他得了第two名。`였다.

## 읽기

한자와 로마자는 그대로 두고, 숫자와 기호만 한자 숫자로 바꾼다. 한자 읽기는 TTS 모델이 한다.

| 범주 | 예 |
|---|---|
| 정수 | 1005 一千零五, 10050 一万零五十, 110 一百一十, 12,345 一万二千三百四十五 |
| 二/两 | 2个 两个, 2点 两点, 2000名 两千名, 第2名 第二名, 2月 二月, 2楼 二楼 |
| 연도 | 1990年 一九九零年, 1998那年, 2024-2025赛季 二零二四到二零二五 (2000年前·2000年历史는 수) |
| 날짜 | 2024-10-11, 2024/10/11, 2024.10.11 → 二零二四年十月十一日 |
| 시각·기록 | 14:05 十四点零五分, 0:30 零点三十分, 用时2:05:30 两小时零五分三十秒, 8:00-17:00 八点到十七点 |
| 점수·비율 | 以21:19 二十一比十九, 16:9 十六比九, 3:2 (분이 한 자리이거나 60 이상, 단서 比分·以·战平 등) |

| 분수 | 2/5 五分之二, ½ 二分之一, 1又1/2 一又二分之一 |
| 음수·온도 | -3 负三, -5℃ 零下五摄氏度, -5~3℃ 零下五到三摄氏度 |

| 기호·이모지 | CLDR 48.2 중국어 이름 (🍔 汉堡), `resources/unicode-fallback/zh.*` |

정책:
- 단위 기호 앞 수는 二를 쓴다(二百二十伏). 셈 단어(两 양사) 앞 2와 百·千·万·亿 앞 첫 2는 两을 쓴다.
- 번호 단서는 앞 6자 안에서, 전화 단서는 앞 5자 안에서 찾는다. 전화번호의 1은 幺로 읽는다. 0으로 시작하는 수는 한 자리씩 읽는다.
- 로마자 뒤 세 자리 이상은 한 자리씩(CA1234), 두 자리 이하는 수로(G20) 읽는다.

## 자원과 계약

- 코드: `languages/zh-CN/pack.c`, `validate.c`, 라우팅은 `src/core/normalize.c`의 `han_sentence`.
- 자원 `resources/languages/zh-CN/rules/`:
  - `context.tsv`: declared_only, han_sentence, classifier_priority
  - `numeric.tsv`: 숫자어, 분수 문자
  - `units.tsv`: 단위·통화
  - `cues.tsv`: 两 양사, 번호·전화·방·연도·점수·기록 단서, 범위 단위
  - `foreign.tsv`: 간체가 아닌 글자
- 계약 `zh_pack_v64`(54건)는 구현 전에 작성했다. 라우팅 3건은 "Was:"로 이전 출력을 적었다.

## 측정

평가셋 `benchmark/datasets/zh-tn-eval`(322문장, 채점 구간 346개):

| 시스템 | 구간 | 문장 |
|---|---|---|
| 우리 (요청 언어 zh-CN) | 346/346 (100%) | 322/322 (100%) |
| 우리 (한국어 요청, 한자 문장 라우팅) | 339/346 (98.0%) | 315/322 (97.8%) |
| 우리 (영어 요청, 한자 문장 라우팅) | 339/346 (98.0%) | 315/322 (97.8%) |
| wetext (VoxCPM2 내장) | 296/346 (85.5%) | 272/322 (84.5%) |
| NeMo zh | 231/346 (66.8%) | 207/322 (64.3%) |

- 라우팅 요청에서 남은 7건은 한자가 하나도 없는 수식 문장(`1+1=2。`)이다. 중국어 근거가 없으니 요청 언어로 읽는 것이 정책에 맞다.
- **주의:** 평가셋과 팩을 같은 사람(Claude)이 만들었고, 팩은 이 평가셋의 빈틈을 보고 만들었다. 100%는 과적합을 포함한 숫자이며 일반 성능의 추정치가 아니다. 새 문장으로 만든 held-out 평가셋이 필요하다.
### held-out 평가셋 (2026-10-11)

`zh-tn-heldout-v1`(496문장, 채점 구간 609개)을 따로 만들었다.
- 작성: 팩도 1차 평가셋도 보지 않은 작성자 둘
- 검수: Claude가 원어민으로 했고, 시스템 출력을 보기 전에 정답을 고정했다

| 시스템 | 구간 | 문장 |
|---|---|---|
| 우리 (요청 언어 zh-CN) | 533/609 (87.5%) | 424/496 (85.5%) |
| 우리 (한국어·영어 요청 속 한자 문장) | 529/609 (86.9%) | 420/496 (84.7%) |
| wetext | 460/609 (75.5%) | 351/496 (70.8%) |
| NeMo zh | 366/609 (60.1%) | 264/496 (53.2%) |

1차 평가셋의 100%는 과적합이었다. 일반 성능은 87.5% 수준이다. 우리가 틀린 76구간의 유형:
- **수식(17):** 문자로 시작하는 식(y=x², a²+b²), 위첨자 지수(2³, 10²³), ≥ π ∠ ∛ sin, 분수끼리의 식
- **단위 기호(17):** mmHg, kW·h, kcal, nm, ms, ㎡, mmol/L, L/100km가 사전에 없음. GB·Mbps·MB/s 앞 세 자리 이상 수를 한 자리씩 읽음(256GB 二五六GB, 버그)
- **비율·점수(8):** 전각 쌍점 ∶, 세 자리 점수(102:98), 소수 비율(1.05:1), 1:2:3, 테니스 6-4
- **연도(5):** 1000年(기간), 2030年前(그 전), 2019款, 90后·00后(九零后)
- **날짜(4):** 5.1(五一), 12·9, 10/13·11/5를 분수로 읽음
- **번호(5):**
  - 전각 쉼표 뒤 숫자를 그대로 둠(846201，5, 코어 버그)
  - 404를 사백사로 읽음
  - 京A·88V61의 V를 볼트로 읽음
  - 室 없는 방 번호(1203, 501)
- **기타:**
  - ￥ 뒤 元 누락(전각 ￥)
  - 100+·10万+, 2、300年
  - 영상 길이 3:25, 1h20min, 1分58秒32
  - 2成, -0.6‰, 1½, 단위·통화 범위, 버전 V2.3.1
- **엔진 버그:** zh-CN 선언 요청이라도 로마자 단어가 많은 문장(iPhone 16 Pro Max起售价9999元)은 문장 언어 투표가 영어로 가고, 중국어 팩의 내부 표식이 영어로 읽혀 새어 나온다("at zh int").

wetext가 우리보다 나은 범주는 비율(88.9% 대 66.7%), 날짜(93.1% 대 86.2%), 연도(86.7% 대 83.3%)다.
