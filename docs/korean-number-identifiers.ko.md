# 숫자 번호: 하이픈과 긴 숫자 (v0.24)

speech 출력에서 번호로 쓰인 숫자를 금액이나 범위처럼 읽던 문제를 고친다(2026-10-01 결정).

- 하이픈으로 이은 숫자는 계좌번호·전화번호처럼 번호로 읽는다.
- 쉼표도 단위도 없이 이어진 긴 숫자는 한 자리씩 읽는다.

## 1. 하이픈으로 이은 두 숫자 묶음

**기본은 번호다.** 한 자리씩 읽고 하이픈은 `다시`로 읽는다. 전화번호 인식기가 이미 잡은 번호는 그대로 둔다(`1588-0000` 일오팔팔 공공공공).

| 입력 | 이전 | 지금 |
|---|---|---|
| `27022-8080 통장` | 이만 칠천이십이에서 팔천팔십 통장 | 이칠공이이 다시 팔공팔공 통장 |
| `970017-3461793번` | 구십칠만 십칠에서 삼백사십육만… 번 | 구칠공공일칠 다시 삼사육일칠구삼번 |
| `30-520869511 포장` | 서른에서 오억 이천팔십육만… 포장 | 삼공 다시 오이공팔육구오일일 포장 |
| `2020-1234호` | 이천이십에서 천이백삼십사 호 | 이공이공 다시 일이삼사호 |
| `12-34를` | 십이에서 삼십사를 | 일이 다시 삼사를 |

**범위(`에서`)는 후순위다.** 아래 경우에만 범위로 읽는다.

1. 앞 수가 뒤 수보다 작고, 뒤 묶음 바로 다음에 단위나 수 세는 말이 온다. 묶음 길이는 단위·통화·퍼센트면 5자리, 수 세는 말이면 4자리까지다. 숫자에 바로 붙은 한글이 조사가 아니면 수 세는 말로 본다(`3-5세`, `2-3회`, `5-10위안`).
   - 예: `3-4개` 서너 개, `10-20%` 십에서 이십 퍼센트, `1000-2000명`, `7-10일간`
2. 번호에 붙는 말(`digit_label_counter`: 번, 호, 번지, 동, 차)이 오면 한두 자리일 때만 범위로 읽는다.
   - 예: `4-5번 정도` 사오 번, `1234-5678번`은 번호
3. 범위 신호어(`digit_range_cue`: 사이)가 뒤에 온다.
   - 예: `가격은 12000-15000 사이`
4. 뒤에 큰 수 단위(만, 억, 십, 백, 천, 조)가 온다. 이때는 큰 수 범위 문법이 읽는다.
   - 예: `100-200만 원` 백에서 이백만 원
5. 네 자리 연도 두 개다(1000~2999, 차이 100 이하).
   - 예: `2019-2020 시즌` 이천십구에서 이천이십 시즌
6. 뒤 묶음이 줄인 표기이고 수 세는 말이 붙는다.
   - 예: `24-5개월` 이십사에서 오 개월

**경기 점수는 `대`로 읽는다.** 문장에 경기 신호어가 있고 숫자 쌍이 짧으면(각 3자리 이하, 앞자리 0 없음, 단위 없음) 점수로 읽는다. 신호어는 `score_cue` 낱말의 앞부분으로 찾는다(승리, 졌, 비겼, 무승부, 동점, 꺾, 뒤집, 앞서, 경기, 세트, 골 등). 읽기에 쓰는 말은 `policy score_separator 대`로 바꿀 수 있다.

| 입력 | 지금 |
|---|---|
| `25-18로 졌습니다` | 이십오 대 십팔로 졌습니다 |
| `2-0 승리로 끝이 났다` | 이 대 영 승리로 끝이 났다 |
| `102-98로 이겼다` | 백이 대 구십팔로 이겼다 |
| `문의 3-5` (신호어 없음) | 문의 삼 다시 오 |

이 규칙이 없을 때 /jev-eval의 스포츠 인정률이 59.5%에서 53.5%로 떨어져서 추가했다. 그 전의 범위 읽기(이십오에서 십팔)도 틀린 읽기였다.

**범위로 읽게 하려면 `~`를 쓴다**(`12~34`). 이 규칙은 한국어 문맥에서만 동작하며 영어 문장의 `pages 3-5`는 그대로다.

## 2. 9자리 이상 숫자

쉼표 묶음이 없고 뒤에 단위나 수 세는 말이 없는 9자리 이상 숫자는 주문·송장·학번 같은 번호로 보고 한 자리씩 읽는다.

| 입력 | 이전 | 지금 |
|---|---|---|
| `874456932101이` | 팔천칠백사십사억 오천육백구십삼만 이천백일이 | 팔칠사사오육구삼이일공일이 |
| `326253620012더라` | 삼천이백육십이억… 십이더라 | 삼이육이오삼육이공공일이더라 |
| `2017345678번` | 이십억 천칠백삼십사만… 번 | 이공일칠삼사오육칠팔번 |

**금액이나 수량은 그대로다.**

| 입력 | 읽기 |
|---|---|
| `1,234,567,890원` (쉼표) | 십이억 삼천사백오십육만 칠천팔백구십 원 |
| `123456789012원` (통화) | 천이백삼십사억… 원 |
| `1234567890명` (수량) | 십이억… 명 |
| `9800000000달러` | 구십팔억 달러 |

번호에 붙는 말(번, 호 등)은 단위로 치지 않는다. **억·조로 읽게 하려면 기존 제어 구문 `{@sino}`를 쓴다**(annotated 입력).

```text
874456932101{@sino}이 오늘  →  팔천칠백사십사억 오천육백구십삼만 이천백일이 오늘
```

## 3. 설정과 구현

- **리소스:** `resources/languages/ko-KR/rules/numeric.tsv`
  - `policy hyphen_digits identifier|range`: `range`면 이전 읽기로 돌아간다.
  - `policy long_digit_identifier_min 9`: `0`이면 끈다. 7~16 사이로 정할 수 있다.
  - 단어 목록: `digit_label_counter`, `digit_range_scale`, `digit_range_cue`
- **분류기:** `languages/ko-KR/identifiers.c`의 `ttf_ko_classify_digit_identifier`. speech 출력에서만 동작한다.
- **엔진 공통 코드:** `src/core/normalize.c`. 우선순위 100 이상인 언어 팩 규칙은 공통 숫자 문법이 뒤의 수 세는 말까지 더 길게 잡았어도 이긴다(`27022-8080 통장`의 통, `2019-2020 시즌`의 시). 다만 전화번호 인식 결과와, 공통 문법이 이미 번호로 판정한 결과는 대체하지 않는다.
- **계약:** `tests/evaluation/ko_number_identifiers_v24.jsonl` 29건(점수 5건 포함). 구현 전에 작성했다.
- **바뀐 기존 계약:** 정책 변경으로 기대값이 바뀐 기존 계약 12건은 notes에 이전 값을 남겼다.
  - 단위 없는 짧은 쌍(`5-3`, `문의 12-34`)은 이제 번호로 읽는다. `경기는 3-2로 끝났다`는 점수로 삼 대 이로 읽는다.
  - 큰 수 띄어쓰기 계약 5건은 금액 읽기를 계속 시험하도록 입력에 `명`을 붙였다(`100000001명` 일억 일 명).

## 4. 측정

- 한국어 벤치마크(보정 variant): 76.97% → **78.59%**. 새로 맞음 1,873문장, 새로 틀림 1문장(참조가 `63-40번지`를 육십삼에서 사십 번지로 읽음). 이 가운데 점수 규칙의 몫은 236문장이다.
- 남은 과제: `3-1절`, `6-25 전쟁`은 이제 삼 다시 일절, 육 다시 이오로 읽힌다. 이전의 "삼에서 일절"보다는 낫지만, 관용 읽기(삼일절, 육이오)는 사전 항목으로 다룰 일이다. 쌍점 점수(`40:34로 앞섰다`)는 아직 원문 그대로 남는다.
