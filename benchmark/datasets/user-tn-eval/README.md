# 소유자 TN 평가셋 (user-tn-eval)

프로젝트 소유자가 만든 언어별 1,000문장 평가셋이다(2026-10-13). 언어는 ko-KR, en-US, ja-JP, zh-CN, vi-VN이다.

- **작성:** 소유자가 언어별 지시문(`tn-eval-prompts-by-language.md`)을 다른 에이전트에 주어 만들었다. 이 저장소의 코드는 보지 않았다.
- **원본:** `src/<lang>.tsv`는 받은 그대로 두고 고치지 않는다.
  - 형식은 `category<TAB>markup<TAB>note`이다.
  - 마크업은 zh-tn-eval과 같다: `{원문|읽기}`, `a/b`, `[x,y]`, `(x)`.
- **빌드:** `python3 -I benchmark/datasets/user-tn-eval/build.py` → `user-tn-<lang>.jsonl`
- **측정:** `python3 -I benchmark/evaluators/user_tn_eval.py run|score [--lang …] [--tag 이름]`
  - 결과는 `benchmark/generated/user-tn-eval/<tag>/`(로컬 전용)에 둔다.
  - ja-JP는 pyopenjtalk가 있는 환경(`~/venv-nemo/bin/python`)에서 돌린다.

## dev / test 분할

- 언어마다 범주별 층화로 **dev 700 / test 300**으로 한 번 나눴다(고정 시드 20261014).
- **dev:** 수정은 dev 오답에서만 고른다.
- **test:** 점수만 본다. 채점기는 test 오답을 파일로 쓰지 않는다.
  - 분할 전에 첫 측정(main ddbd04e)에서 전체 오답 표본을 본 적이 있다. 그래서 test는 완전한 미공개 셋이 아니고 "수정에 쓰지 않는 셋"이다.

## 채점

- 한 구간의 읽기 중 하나가 앞 구간 뒤에 순서대로 나오면 맞은 것으로 센다.
- NFKC로 바꾸고 소문자로 만든 뒤 공백과 문장부호를 지우고 비교한다.
- **언어별 정책 동치:** 두 읽기가 다 맞는 정책 차이만 넣었다. 출력에 맞추려고 넣지 않는다.
  - en-US: 정답의 낱글자(w)는 엔진의 글자 이름(double you)도 받는다.
  - ja-JP: 가타카나는 히라가나로 본다. ー는 앞 모음으로 보고, 어느 쪽이든 생략해도 받는다(に = にー).
    출력에 남은 한자는 pyopenjtalk 가나 읽기로도 비교한다.
  - zh-CN: 〇 = 零, 圆 = 元, 两百·两千·两万·两亿 = 二…, 点半 = 点三十(分).
  - vi-VN: gi-ga = ghi-ga, đề-xi-ben = đê-xi-ben(표기 변이).
  - ko-KR:
    - 시각의 고유어 시(스물세 시 = 이십삼 시)
    - 글자+한 자리 숫자의 영어 읽기(B7 비세븐 = 비 칠, 정책 결정 2026-10-14)
    - 에잇 = 에이트
    - 하이픈 `다시` = `에` 또는 무음(기존 한국어 정책 차이, HANDOFF "정책 차이로 남긴 한국어 유형")
- **줄별 보완:** `amend.tsv`에 둔다(언어, 줄, 원래 읽기, 넓힌 읽기, 이유).
  - 빌드가 원래 읽기가 그대로인지 확인하므로 원본 기록이 남는다.
  - dev에서 본 줄만 넓혔다. test 줄은 보지 않으므로 넓히지 않았다.
